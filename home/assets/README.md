## Prompt specifications

All three prompts requested a highly polished, realistic 3D product-interface representation with a genuinely transparent background, clean alpha edges, warm off-white surfaces, charcoal interface elements, and restrained deep-teal `#146c68` accents. They prohibited logos, trademarks, watermarks, readable generated text, scannable QR codes, government visual language, institutional blue, shields, padlocks, server racks, clouds, and decorative particles.

- **Hero:** one selected desktop browser field, one adjacent QR panel, and one phone held naturally and aimed at the QR, composed as a tight landscape product cutout.
- **Choose field:** an extremely tight crop around one focused browser field, pointer, and abstract context-menu command, with no phone or QR.
- **Scan and send:** one phone and hand, one non-scannable QR representation, one large input control and send button, and a subtle return cue toward a partial desktop field.

The images are representations of the interaction, not screenshots and not evidence of protocol behavior. The accessible alternative text and surrounding HTML provide the authoritative product explanation.

The homepage appends the first eight hexadecimal characters of each reviewed SHA-256 digest as a URL version. This keeps the files byte-identical while ensuring that browsers and intermediary caches request a new URL whenever a reviewed image changes. The first walkthrough image loads eagerly so it is present when a mobile reader reaches the section.
